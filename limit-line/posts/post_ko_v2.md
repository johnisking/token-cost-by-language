"코딩엔 어떤 모델을 써야 하나요?"라는 질문의 답은 대부분 감입니다. 저는 선을 찾고 싶었습니다. 싼 모델(Claude Haiku 5.5)이 처음 뒤처지는 지점, 즉 소넷이나 오퍼스에 돈을 더 내야 하는 지점입니다.

그래서 윈도우 노트북 한 대에서 코딩 에이전트 5개로 163번을 돌렸습니다. 과제는 단계마다 어려워지고, 결과는 전부 숨은 테스트로 채점했습니다.

**에이전트:** Claude Code(하이쿠 5.5, 소넷 5.5, 오퍼스 5.5), Codex(gpt-6-luna), 구글 Antigravity CLI(제미나이 4 아르곤). 모두 effort medium이고, 매번 빈 폴더에서 시작했습니다.

## 단계

| 단계 | 과제 | 숨은 검사 |
|---|---|---|
| L2 | 레벨 5개, 일시정지, 레벨 건너뛰기, 진행 저장이 있는 벽돌깨기 | 9 |
| L3 | CSV 모듈과 요약 모듈이 있는 여러 파일 가계부 | 12 |
| L4 | 모듈 5개, 화면 3개, 예산, 보고서, 50단계 되돌리기가 있는 가계부 | 23 |
| L5A | 남이 만든 1,032줄 앱에 버그 6개를 심고 증상만 알려 줌 + 기능 3개 추가 | 38 |
| L5B | 스프레드시트 엔진: 연산 순서, 함수, 순환 참조 감지, $절대 참조 복사, 되돌리기 | 38 |
| L6 | 마크다운 변환기 marked에서 2026년 9~10월에 실제로 고쳐진 버그 3개 | 실제 수정의 테스트 + 전체 테스트 |

L6은 실제 수정 직전 코드에서 시작해 사용자 신고문만 줬습니다. 채점은 관리자들이 수정과 함께 넣은 테스트와 marked 전체 테스트(약 1,900개)로 했고, 모델이 고친 `src/` 폴더만 가져와서 테스트를 고쳐 통과시키는 꼼수는 통하지 않게 했습니다.

## 2~5단계: 선이 없었다

| 에이전트 | L2 | L3 | L4 | L5A | L5B |
|---|---|---|---|---|---|
| 하이쿠 5.5 | 5/5 | 5/5 | 5/5 | 4/4 | 2/2 |
| 소넷 5.5 | 5/5 | 5/5 | 5/5 | 4/4 | 2/2 |
| 오퍼스 5.5 | 5/5 | 5/5 | 5/5 | 4/4 | 2/2 |
| Codex | 5/5 | 4/5 | 4/5 | 3/4 | 1/1 |
| 제미나이 4 아르곤 | 5/5 | 5/5 | 5/5 | 2/2 | 1/1 |

(만점 받은 실행 수 / 실행 수)

**요구사항이 분명하면 하이쿠는 한 번도 실패하지 않았습니다.** 순환 참조까지 감지하는 스프레드시트 엔진을 만들었고, L5A에서는 증상만 보고 버그 6개를 다 고친 뒤 기능 3개를 넣으면서 기존 테스트 23개를 하나도 깨뜨리지 않았습니다. L6의 쉬운 버그와 중간 버그도 거의 모든 실행이 풀었고, 하이쿠와 소넷은 14~20초면 끝났습니다.

## 어려운 버그: 여기서 모델이 갈렸다

L6 어려운 버그는 `` `C:\Users\` ``처럼 백슬래시로 끝나는 코드 구간이 있으면 같은 줄 뒤쪽의 `**굵게**`가 안 먹는 문제입니다. 관리자가 넣은 테스트에는 사례가 7개 있고, 고치기 전 코드도 그중 3개는 통과합니다.

완전히 고친 실행은 하나도 없었습니다. 하지만 실패한 모양은 모델마다 달랐습니다.

![어려운 버그에서 실행마다 통과한 테스트 사례 수](https://tokensave.app/ai-coding-limit-line-chart.png?v=2)

| 모델 | 테스트 | 실행별 통과 사례 (7개 중) | 다른 테스트를 깨뜨림 |
|---|---|---|---|
| 하이쿠 5.5 | 없음 | 5, 5, 5, 5, 5 | 1회 (15개) |
| 하이쿠 5.5 | 허용 | 5, 6, 5, 5, 5 | 0 |
| 소넷 5.5 | 없음 | 6, 6, 5, 6, 6 | 0 |
| 소넷 5.5 | 허용 | 6, 6, 6, 5, 6 | 0 |
| 오퍼스 5.5 | 없음 | 6, 6, 6, 5, 0* | 1회 |
| 오퍼스 5.5 | 허용 | 6, 6, 5, 5, 6 | 0 |
| Codex | 없음 | 3, 3, 4, 4, 4 | 3회 (2개씩) |
| 제미나이 4 아르곤 | 없음 | 3, 3, 3 | 0 |

\* 이 오퍼스 실행은 소스에 잘못된 정규식을 남겨서 marked가 아예 불러와지지 않았고, 모든 테스트가 실패했습니다.

모든 실행이 신고문에 적힌 예시는 고쳤습니다. 남은 건 코드 구간 **안에 백틱이 들어 있는 경우**(``_``\`_`` `` 같은 것)로, 신고문에는 없던 경우입니다. **소넷은 10번 중 8번, 오퍼스는 10번 중 6번 7개 중 6개를 맞혔고, 하이쿠는 10번 중 1번이었습니다.** 신고에 없던 경계 사례 하나, 이게 제가 찾던 선입니다.

## "테스트를 못 돌렸잖아"라는 반론

처음 측정에서는 어떤 에이전트도 marked 테스트를 돌릴 수 없었습니다. 패키지가 설치돼 있지 않았고, Claude Code는 셸을 쓸 수 없었습니다. 실제 개발자는 테스트를 돌려 가며 고치니, Claude 모델마다 5번씩 더 돌렸습니다. 의존성을 미리 설치하고, `node`, `npm test`/`npm run`, 읽기 전용 git을 허용했습니다(설치와 네트워크는 계속 막음).

이 15번은 모두 전체 테스트를 실제로 돌렸고, 대부분 재현 스크립트도 직접 만들어 확인했습니다. **그래도 맞힌 사례 수는 달라지지 않았습니다.** 달라 보인 건 피해 하나였습니다. 테스트 없이 돌린 Claude 15번 중 2번이 다른 곳을 망가뜨렸고(테스트 15개를 깨뜨린 하이쿠, marked가 아예 안 불러와지게 만든 오퍼스), 테스트를 허용한 15번은 0번이었습니다. 다만 횟수가 적어 우연일 수 있으니, 테스트가 이를 막는다고까지는 말하지 않겠습니다.

즉 이 버그에서 테스트는 신고문이 빠뜨린 경우를 떠올리게 해 주지 못했습니다. 다른 코드를 덜 망가뜨리게 할 수는 있지만, 이번 횟수로는 확인되지 않습니다.

Codex도 테스트를 허용해 돌렸지만, 윈도우 샌드박스가 5번 모두 esbuild 빌드를 막아서 제외했습니다. 제미나이는 사용 한도를 다 쓴 상태였습니다.

## 비용

Claude Code는 실행마다 API 가격 기준 비용을 알려 줍니다. 1회 평균입니다.

| | 하이쿠 5.5 | 소넷 5.5 | 오퍼스 5.5 |
|---|---|---|---|
| 전체 단계 | $0.026 | $0.19 | $0.45 |
| 어려운 버그, 테스트 없음 | $0.012 | $0.12 | $0.39 |
| 어려운 버그, 테스트 허용 | $0.031 | $0.22 | $0.48 |

전체 단계 기준으로 하이쿠는 오퍼스보다 1회당 약 94% 적게 들었습니다.

## 그래서 어떻게 쓰면 되나

- **요구사항이 분명하면 하이쿠로 충분합니다.** 명세대로 만들거나 증상이 적힌 버그를 고치는 일에서는 하이쿠가 오퍼스와 같은 만점을 받았고, 1회 비용은 약 94% 적었습니다.
- **신고가 불완전한 실제 버그는 소넷이나 오퍼스가 낫습니다.** 빠진 경계 사례를 챙긴 횟수가 10번 중 8번·6번으로, 하이쿠(10번 중 1번)보다 훨씬 많았습니다. 이 버그에서는 소넷이 가장 잘했고 1회 비용도 오퍼스보다 쌌지만($0.12~0.22 대 $0.39~0.48), 10번씩이라 소넷과 오퍼스의 차이는 우연일 수 있습니다.
- **어떤 모델이든 테스트는 돌리게 하세요.** 이번엔 빠진 경우를 찾아 주지 못했고, 테스트를 허용한 실행 중 다른 코드를 망가뜨린 경우는 0번이었습니다(테스트 없이는 15번 중 2번, 횟수가 적어 테스트 덕분인지는 확실하지 않음).
- **경계 사례 검토는 여전히 사람 몫입니다.** 완전히 고친 모델은 없었고, 모두 놓친 경우는 관리자만 떠올린 경우였습니다.

## Antigravity 이야기

Antigravity 무인 모드는 허용되지 않은 명령이 한 번만 거절돼도 작업 전체가 끝납니다. 읽기 전용 명령만 허용했더니 제미나이가 몇 분씩 코드를 읽다가 `node -e`로 확인하려는 순간 멈춘 경우가 여러 번 있었습니다(윈도우에서는 따옴표가 든 명령에 정확히 일치하는 규칙이 필요합니다). 전체 권한으로 다시 돌리자 쉬운 버그와 중간 버그는 풀었지만 2~11분이 걸렸고, 어려운 버그 한 번은 30분 제한을 다 쓰고도 고치지 못했습니다.

## 한계

- 모델 간 차이는 한 프로젝트의 어려운 버그 하나, Claude 모델당 10회에 기댄 결과입니다.
- 2~5단계는 칸마다 실행이 1~5회뿐이고, 프롬프트에 테스트가 쓰는 id와 함수 이름이 다 적혀 있어 실제 일보다 쉽습니다.
- 테스트 허용 비교는 Claude 세 모델만 해당합니다.
- 도구마다 모델 외에도 다른 점이 있습니다(샌드박스, 권한, 거절된 명령에서 멈추는 방식).
